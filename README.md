# Alma Technology CRM

Закрытая CRM для небольшой команды менеджеров. Публичный сайт остаётся по `/ru` и `/en`, CRM — по `/ru/crm`.

## Первый локальный запуск

1. Скопируйте `.env.example` в `.env.local` и задайте `BETTER_AUTH_SECRET` (длинное случайное значение) и `BETTER_AUTH_URL`.
2. Выполните `npm install`.
3. Выполните `npm run db:migrate`.
4. Однократно задайте `ADMIN_NAME`, `ADMIN_LOGIN`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` в окружении и выполните `npm run db:create-admin`.
5. Выполните `npm run dev` и откройте `http://localhost:3000/ru/crm/login`.

После создания первого администратора новые учётные записи создаются в CRM, в разделе «Команда».

## Docker

В `docker-compose.yml` уже добавлен постоянный volume `alma_crm_data`. При запуске контейнер сам применяет миграции, затем запускает сайт. В production обязательно задайте публичный URL в `BETTER_AUTH_URL`; он должен совпадать с адресом, с которого сотрудники открывают CRM.

## Backup

`npm run db:backup` создаёт согласованную SQLite-копию в `data/backups`. Для контейнера эту команду следует выполнять внутри контейнера, чтобы архив оказался в постоянном volume.

## Что учитывает CRM

- совмещаемые роли Lead Researcher, Verifier, SDR / Setter и Closer;
- конвейер `RAW → VERIFIED → SDR → CONTACTED → REPLIED → INTERESTED → QUALIFIED → DISCOVERY → OFFER → NEGOTIATION → PAYMENT PENDING → WON`;
- независимые проверки качества Researcher, Verifier и SDR с обязательными причинами возврата;
- неизменяемую атрибуцию: кто нашёл, проверил, первым связался, квалифицировал и закрыл;
- найденную проблему, решение, decision maker, бюджет, срок, пакет и результаты Discovery;
- утверждённые ценовые коридоры и автоматическую отметку `Needs Technical Estimate`;
- журнал контактов, отправленное, ожидания, задачи, просрочку и план на сегодня;
- передачу клиента, историю ответственных и возврат просроченного 90-дневного владения в общий пул;
- стоимость договора отдельно от фактически полученных денег;
- комиссии Researcher 3%, Verifier 2%, SDR 5% и Closer 10% только от `Cash Received`;
- KPI по ролям, воронку, конверсии, качество follow-up, средний чек, цикл продажи, источники и выручку на лид.

## Правила учёта

- Сделка становится `WON` только после ввода положительной фактически полученной суммы.
- Причина обязательна для отклонения Verifier, возврата SDR, плохой квалификации и проигранной сделки.
- Первый исходящий контакт переводит проверенный лид в `CONTACTED`; входящий контакт — в `REPLIED`.
- Задача считается выполненной вовремя для KPI SDR только если `completed_at <= due_at`.
- Валюты в финансовых отчётах никогда не складываются между собой.
